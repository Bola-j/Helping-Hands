# Phase 1 backend, database, local containers and CI: delivery breakdown

Planning date: 11 November 2026 (Africa/Cairo). Target: **12 November 2026**, subject to team capacity and dependency availability. This is a high-risk forecast, not a commitment or evidence of completion. It covers the complete Phase 1 backend scope, local infrastructure and API CI in the [demo roadmap](api-demo-scrum-roadmap.md); production deployment and the separate web implementation remain later work. API CI is pulled forward from [P2-DEP-02](https://github.com/Bola-j/Helping-Hands/issues/50). Existing tickets remain the tracking items; no duplicate tickets are implied.

**Reconciliation — 22 November 2026:** the backend API-client rehearsal (P1-58) is complete and documented in [the dated evidence record](p1-58-backend-rehearsal.md). This closes the backend rehearsal deliverable only; P1-47 browser rehearsal and P1-48 evaluation evidence remain separate.

## Current starting point

The working tree contains uncommitted API, EF migration, Docker and test work. The historical assessment in the [SRS](SRS.md#appendix-phase-1-implementation-baseline-and-verification) recorded a successful build, nine tests and an isolated empty-PostgreSQL migration on 9 November; those results are not a current end-to-end demonstration. Code inspection shows existing auth, application, request, referral, outcome and attachment routes, but several Phase 1 rules and models are missing. GitHub Actions workflows are absent. Docker was unavailable during this planning pass; the configured S3 image previously failed to pull. Recheck all dependencies before committing to the target.

P1-01 is done. P1-02 is in progress: the Scrum Master accepted the review, while Phase 1 diagram reconciliation remains open. The Scrum Master chose an interim [P1-33](https://github.com/Bola-j/Helping-Hands/issues/33) rule: allow only exact-version matches for older needs until reviewed; leave unmatched needs open. Implementation and tests remain outstanding.

## Execution checkpoints

- **Start now:** confirm Docker engine, S3 image availability and team availability; implement the recorded interim P1-33 decision. Ziad owns rows 2–3, 6 DB and 7–8; Bola owns rows 1, 4–5 and the CI skeleton. Coordinate model and endpoint contracts before API integration.
- **Next:** after the schema and shared lock protocol, finish rows 9–11. Develop reminder and outcome work in parallel where their prerequisites permit. Keep each ticket and feature branch single-responsibility.
- **Before the target:** run rows 12 and 14–16, including a real CI run. Close a ticket only when its own acceptance criteria, review and evidence are complete. If Docker, the matching implementation or capacity blocks a critical path, make the blocker visible on the Project immediately.
- **Fallback:** if all rows cannot be completed and verified by 12 November, prioritize a truthful API-client charity approval → request → referral → protected outcome → coordinator review/closure slice and a working local stack/build pipeline. Record every omitted Phase 1 feature, missing automated check and open ticket; the fallback is partial progress, not completion of the full Phase 1 backend.

## Review and evidence

Run focused unit and HTTP tests for allowed and denied roles, intake confirmations, pending/rejected charity eligibility, missing evidence, review and explicit closure. Use real isolated PostgreSQL for migration, uniqueness, locks and race checks; use a real isolated S3-compatible service and email catcher for integration checks. Validate empty and upgrade migrations, restart persistence and failed dependency responses. Retain exact commands, CI run links, actual results and unverified recovery behavior; do not treat stub storage, a successful build or an endpoint list as end-to-end proof. No production deployment is authorized or claimed by this plan.
